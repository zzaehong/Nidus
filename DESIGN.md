# Technical design

## Boundary and runtime units
One synchronous Python CLI process operates a user-selected Agent Vault. One
Employee (`worker-1`, Operations / document analyst) has persistent Home identity
without model assignment. Runtime orchestrates Inbox, Task Board, Desk, Security,
Meeting Room, Workshop and verification. The briefing is a deterministic
Intelligence Layer operation; no generative provider is called.

## Ownership and persistence
SQLite `.nidus/state.sqlite3` owns requests, contracts, Task Board, Home pointers,
Desk native notes/reference checkpoints, decisions and audit events. Library is
explicit user `.md`/`.txt` files outside `.nidus`. Workshop writes one output.
Archive is a retained Completed row, exposed through a separate query; no copying
or deletion of task truth. Each transition commits transactionally. A process
flock guards all mutating operations. SQLite schema version is checked on open.
Portable Home contains no machine paths or secrets. Vault Git is mandatory:
initialization creates a repository if absent; each mutation stages only Nidus
state, its runtime ignore file and the task's explicitly selected sources/output
and creates a local commit. Approved replacement preimages are committed before
writing. Runtime locks/journals are ignored. Unrelated staged files remain staged;
hooks and commit signing are disabled for these local checkpoints. No remotes are touched.

## State transitions and interfaces
`init`, `submit`, `run`, `decide`, `list`, `show` via `python3 -m nidus --vault PATH`.
Queued → Running → Verifying → Completed. Running → Waiting (overwrite),
Waiting → Queued (approve) / Cancelled (reject). Errors → Blocked; explicit run
can retry Blocked. A persisted Running task recovers execution; Verifying recovers
verification. `run --execute-only` checkpoints before verification for recovery
testing. Terminal tasks are not executable.

## Context recovery
Home identity → last Desk checkpoint → current Board → selected Library only.
Board overrides stale task references. Desk native notes survive and every
checkpoint is retained. The recovered next action is derived from Board status,
not trusted from old Desk. Single-worker Home tracks the selected task and clears
its pointer at terminal completion/cancellation.

## Permission / failure boundaries
Security validates every read/write before tool use: no absolute, `..`, symlink,
hidden components, non-regular files, source overwrite or unsupported suffixes.
No arbitrary code tools exist, so Docker adds no protection to this slice.
Existing destination asks the human; decision scope includes source and output
hashes. Approval cannot expand allowed paths. Files are rechecked before writing;
new outputs use exclusive creation, replacements use atomic rename. Process
failure between a file write and DB commit is reconciled from the contract on
retry. Verification checks independent regenerated bytes and source hashes.
Corrupt DB/schema fails closed; Git checkpoint failures report an error, block
affected tasks and clear completion results rather than claim tracked success.
Cross-resource DB/filesystem/Git writes are not one transaction. Explicit retry
can reconcile the recorded write intent and commit after a Git failure. Untrusted
external processes racing path changes are outside this cooperative local model.

## Decisions: alternatives and replacement
- SQLite vs JSON files: SQLite gives transactionality and audit ordering without
  dependencies. Database access stays in Store and can be replaced.
- CLI vs web GUI: CLI gives an executable vertical slice without server/UI scope;
  Inbox matrix remains deferred, concept document unchanged.
- Synchronous process vs queue/daemon: one worker needs no scheduler. Persisted
  phases enable restart without a queue.
- Deterministic worker vs external model: no credentials/cost/data transmission;
  honest evidence extraction validates orchestration, not generative reasoning.
- Allowlisted file operations vs Docker: no shell/network execution; application
  boundary sufficient for trusted local use. Revisit sandbox before adding tools.
- Logical archive vs separate files: one source of truth avoids move inconsistency.

## Verification / local development
`python3 -m unittest discover -s tests -v` covers contracts, completion guards,
crash checkpoints, approval invalidation, path attacks, archive and locking.
`python3 -m compileall -q nidus tests` checks syntax. A real temporary-vault CLI
flow exercises separate processes and Git history. No third-party build/lint tool
is required. AC mappings and commands live in docs/plans/current-plan.md.

## Change candidates
Generative model adapter with network/Secret approval, natural-language contract
formation, matrix GUI, robust OS sandbox and adversarial TOCTOU protection,
multi-worker execution, long-term knowledge promotion. None changes v2 silently.

## Model Gateway extension (2026-10-08)
The new prompt explicitly authorizes opt-in external generative execution. Keep
Home identity, Store schema, file Security, Git, archive and deterministic tests.
Task JSON adds mode, non-secret policy, literal requirements, transmission
snapshots, retained generation and attempt metadata. No schema migration needed.

### Options / decisions
- Vendor SDK vs stdlib HTTP: one Chat Completions JSON adapter uses urllib,
  replaceable behind `Gateway.generate`; works with a direct compatible API,
  OmniRoute or a local compatible server. No package/runtime installation.
- Install OmniRoute vs call a free upstream: use direct OpenCode Zen free model
  first, avoiding router daemon setup. OmniRoute remains a configurable endpoint,
  not a dependency. Source: https://github.com/diegosouzapw/OmniRoute and
  https://opencode.ai/docs/zen/ (researched 2026-10-08).
- Automatic multi-provider discovery vs explicit route list: JSON policy fixes
  ordered routes (free/paid/local), model and credential env-var name. No implicit
  paid fallback. Every allowed route is included in approval. Free classification
  is an operator assertion, not a billing guarantee from Nidus.
- Replay model for verification vs retained candidate: save response before file
  write; independent deterministic verifier checks nonempty content, finish reason,
  literal requirements, source snapshots and exact generated artifact bytes.
  Semantic adequacy is reviewed in live evidence, not proven by a hash.

### Network and credentials
Only `https` remote endpoints; `http` allowed solely for literal loopback hosts.
No URL credentials/query/fragment, redirects or environment proxy inheritance.
Credentials are optional named environment values, never config values. Validate
limits/types before any call. Secret values are rejected from task/source/model
text; error bodies are discarded. No Secret Store scanning or ambient credential
reuse. A configured endpoint is trusted; local router may forward externally and
still requires transmission approval. Known credential matching is defensive,
not general DLP for arbitrary unknown secrets.

Transmission snapshot covers task request, source paths/hashes, full canonical
prompt hash/size and complete route policy including costs/paid opt-in. Waiting
records background, decision choices/effects and scope. Changed input or policy
needs a new decision. Output replacement permission is obtained first. Only exact
selected source text plus work request is sent; no native notes, DB or Vault paths.
Prompt treats source text as data. Model output is inert text, never tool commands.

### Failures, recovery and usage
One bounded attempt per configured route; fallback only for retryable rate/quota,
timeout/network/5xx, within the approved list. Auth/config/invalid/truncated output
fail closed without fallback. No infinite retry; rerun is explicit. Persist each
attempt start/result with UTC time. A retained generation is reusable only for
its source/prompt/policy fingerprint and after requirements pass. Verifying never
calls a provider. Crash before response persistence may require another call on
explicit retry; exactly-once remote execution is not promised. Git failure keeps
existing completion failure guard. Provider token counts/cost are used if known;
otherwise null, not fabricated. A configured zero cost for live free models is a
policy estimate, not a billing receipt.
