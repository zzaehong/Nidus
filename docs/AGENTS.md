# 개발 에이전트 작업 지침

## 기준 문서와 현재 구현

작업 전에 현재 `develop`, 작업 트리와 [Git Flow](Git_Flow.md)를 확인합니다. 사용자 변경을 보존하고 최신 `develop`에서 작업합니다.

- [CONCEPT](CONCEPT.md): 장기 AI Office 방향. 현재 기능 목록으로 해석하지 않습니다.
- [README](../README.md): 설치, 첫 연결, 프로그램 호출과 운영 명령.
- [ROUTER](ROUTER.md): 현재 API 계약, 라우팅, 비용, 저장·접근 정책.
- [VALIDATION](VALIDATION.md): 검증 실행 방법과 시점별 실제 결과.

현재 구현은 Python의 독립 패키지 `nidus_router`입니다. FastAPI·HTTPX·SQLite와 서버가 제공하는 HTML/CSS/JavaScript 대시보드를 사용합니다. 기존 `nidus` CLI, Vault, Manager·Worker, Plan Runtime과 과거 GUI는 현재 소스에 포함되지 않습니다. Git 이력에 있다는 이유로 복원하거나 연동하지 않습니다.

## 구조와 변경 원칙

```text
프로그램 → 전용 API → Router → 공급자 어댑터 → 외부 AI API
대시보드 → 관리 API → 설정·모델 목록·승인·예산
```

- `router.py`: 설정 스냅샷, 후보 순서, 프롬프트, 검증, 대체 호출.
- `providers.py`: 공급자 프로토콜과 응답·SSE·사용량 변환.
- `discovery.py`, `catalog.py`: 모델 조회와 호환성·공식 요금 판정.
- `store.py`, `secrets.py`: SQLite 설정·예산·기록과 OS 자격 증명 저장소.
- `app.py`, `boundary.py`, `static/`: API, 로컬 접근 경계, 대시보드.

라우팅 코어가 FastAPI나 화면에 의존하지 않게 유지합니다. 공급자의 정체성과 API 프로토콜은 구분합니다. 같은 공급자 모델도 연결이 다르면 별도 후보이며, 공개 API에는 라우터가 발급한 모델 ID를 사용합니다.

현재 요청 범위에서 필요한 가장 작은 변경을 구현합니다. AI 기반 라우팅, Agent Runtime, 스케줄러, 대형 플러그인 구조 등 후속 기능을 임의로 추가하지 않습니다.

## 유지해야 할 계약

- 자동 선택은 무료 우선입니다. 지정 모델은 먼저 시도하고 명시한 대체 목록, 나머지 자동 후보 순으로 진행합니다. 후보당 한 번만 호출합니다.
- 요금·호환성이 미확인인 모델과 미승인 유료 모델은 호출하지 않습니다. 유료 호출은 요율·승인·월간 예산 예약이 모두 필요합니다.
- 요청 시작 시 정책을 고정합니다. 오류 후 목록 갱신으로 새 모델이나 변경된 정책을 현재 요청에 끼워 넣지 않습니다.
- 출력 검증 실패와 요청 형식 오류는 대체하지 않습니다. SSE 데이터를 전송한 후 모델을 바꾸지 않습니다. JSON 스트리밍은 호출 전에 거부합니다.
- 사용량이 불명확한 유료 호출은 예약액을 유지합니다. 기록 삭제와 재시작으로 비용 원장을 초기화하지 않습니다.
- 목록에 나타남, 정책상 사용 가능, 실제 호출 성공은 서로 다른 상태입니다. 공식 요금 적용에는 정확한 모델 ID·공식 주소·출처·확인일을 사용하고 무료 계정 조건은 사용자에게 확인합니다.

자세한 조건과 예외는 [ROUTER](ROUTER.md) 및 실제 코드·테스트를 함께 확인합니다.

## 키와 사용자 데이터

공급자 키는 OS 자격 증명 저장소에만 저장하고 SQLite에는 참조만 남깁니다. 키 원문을 소스, 문서, 테스트 fixture, 로그, 오류, API 응답, 프롬프트에 넣지 않습니다. 테스트에는 생성한 가짜 키를 사용합니다.

관리자 인증과 호출용 Bearer 인증을 분리하고 로컬·동일 출처 경계를 유지합니다. 사용자 데이터는 Git 저장소 밖에 보관합니다. 본문 기록은 기본 꺼짐이며 기존 기록·설정·예산을 임의로 삭제하지 않습니다. 실제 호출은 사용자가 허용한 연결과 비용 정책 안에서만 수행합니다.

## 개발 환경과 검증

프로젝트 환경은 **uv**, 개발 Python은 `.python-version`의 **3.13**, 의존성은 `uv.lock`을 기준으로 합니다. 패키지의 선언된 지원 범위는 Python 3.11 이상이며, 3.13 테스트 성공을 모든 버전 검증으로 표현하지 않습니다.

```sh
uv sync --locked
uv run --locked pytest -q
uv run --locked nidus-router serve
uv build
```

각 checkout의 `.venv`를 사용합니다. 전역 Python에 설치하거나 macOS 기본 `python3` 실행을 전제로 하지 않습니다. 의존성은 `uv add`, `uv add --dev`, `uv remove`로 관리하고 `pyproject.toml`과 `uv.lock`을 함께 커밋합니다.

변경에 맞는 테스트를 실행하고 develop 병합 후 전체 회귀 테스트를 실행합니다. 문서만 바꾸는 경우에는 링크·명령·현재 코드와의 일치, 보호 대상 문서의 변경 여부도 확인합니다. 상세 브라우저·루프백 검증 절차는 [VALIDATION](VALIDATION.md)을 따릅니다.

- **PASS**: 실제 실행으로 확인한 성공.
- **FAIL**: 실제 실행에서 확인한 실패. 과거 실패를 삭제하거나 성공으로 바꾸지 않습니다.
- **NOT RUN**: 미실행 항목과 이유.

모의 HTTP와 실제 외부 API 검증을 구분합니다. 실제 호출 없이 공급자 연결 성공을 주장하지 않습니다. 키 비노출, 인증, 예산, 취소·스트리밍 경계는 변경과 관련된 경우 따로 검증합니다.

## Git과 완료 보고

브랜치 생성, 한글 논리 단위 커밋, `--no-ff` 병합, main·원격 변경 범위는 [Git Flow](Git_Flow.md)를 따릅니다. 사용자의 명시적 지시는 기본 규칙보다 우선합니다.

완료 보고에는 변경 내용과 제한, 주요 문서·파일, PASS·FAIL·NOT RUN, 실제 API 검증 여부, 시작 develop·기능 브랜치·커밋·병합·최종 develop, main 변경 여부, push·PR 여부, 작업 트리 상태를 실제 확인값으로 적습니다. 구현되지 않은 장기 구상과 현재 기능을 섞지 않습니다.
