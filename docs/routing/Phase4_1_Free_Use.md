## 실행 직전 Tier 확인

`UsageLedger.reserve()`의 기존 `BEGIN IMMEDIATE` 안에서 revision, 난이도별 허용 Tier,
**Provider + 정확한 Model ID로 조회한 현재 Tier 배정**을 확인하고 예산 예약을 기록한다.
배정 행이 없거나 선택된 Tier와 다르면 `model_tier_mismatch`로 기록하고 API로 전송하지 않는다.
revision이 같은 상태에서 모델 배정이 바뀐 경우도 차단한다. 자동 예약에는 예산 예외를 허용하지 않는다.

모델 Tier 변경이 예약보다 먼저 커밋되면 새 배정을 검사한다. 이미 예약 후 전송된 요청을 설정 변경으로
취소하거나 되돌리지는 않는다. 기존 장부, 예약 및 전환 기록은 삭제하지 않는다.

## 무료 사용 상태와 승인

| 상태 | 의미 | 초기값 및 기록 |
| --- | --- | --- |
| verified | 사용자가 공식 조건과 현재 계정·프로젝트의 무료 자격을 직접 확인 | 확인 체크 필요, `user-account-attestation` 표시 |
| unverified | 현재 계정의 무료 사용 또는 남은 할당량 미확인 | 무료 지원 모델의 기본값. 지원 자체도 unknown이면 이 상태이며 승인은 불가 |
| unavailable | 사용자가 무료 소진 또는 무료 사용 불가를 확인 | 확인 체크 필요, 해당 모델의 별도 승인은 꺼짐 |
| unsupported | 검토된 가격 자료에 무료 티어 없음 | 가격 레코드에서 판단하며 사용자가 무료라고 덮어쓸 수 없음 |

상태, 확인 시각, 공식 가격 출처 URL, 제한 조건, 모델별 승인 여부를 SQLite에 저장한다.
`verified`는 **사용자 계정 확인 기록**이며 Provider API가 무료 잔량을 검증했다는 뜻이 아니다.
확인 시점 이후 계정 조건은 바뀔 수 있다. 남은 무료 토큰·요청 수·크레딧을 생성하거나 추정하지 않는다.

SwiftUI **Tier 및 라우팅**의 모델 행에서 무료 지원 여부, 상태, 시각, 확인 방식, 조건을 확인하고
**무료 사용 상태 확인 · 모델별 호출 승인**을 연다. 상태 확인과 호출 승인은 별도 항목이다.
미확인 모델 승인에는 “과금될 수 있음을 이해하고 기존 예산 내 호출을 승인” 체크가 필요하다.

**이 승인은 특정 무료 티어 지원 모델의 잠재적 과금에 대한 제한된 동의다.** 전체 자동 유료 허용이
꺼져 있어도 그 모델만 시도할 수 있다. 다른 유료 모델로의 전환 권한을 주지 않는다.
전체 자동 유료 허용이 켜져 있으면 기존과 같이 허용 Tier·예산 범위에서 유료 후보도 선택할 수 있다.

모든 경우 가격을 0으로 바꾸지 않는다. `verified`도 현재 구현에서는 유료 가격 상한을 예약한다.
전체·Provider·단일 요청 예산이 필요하며 Provider 예산 0은 이 경로에서도 차단한다. 따라서 실제 무료
계정이어도 예산을 설정하지 않으면 실행하지 못하거나 보수적인 상한 때문에 차단될 수 있다.
수동 채팅은 기존 명시적 수동 호출 및 Budget Guard 정책을 유지한다.

승인은 당시 API 키의 SHA-256 식별값에 연결한다. 키 원문은 SQLite나 로그에 저장하지 않으며 식별값도
설정 응답·전환 로그에 내보내지 않는다. 실행 직전 실제 키의 식별값을 다시 확인한다. CLI 환경변수로
다른 계정 키를 사용해도 이전 모델별 승인으로 실행할 수 없다. 재연결·키 교체·연결 해제 시 무료 확인과
모델별 승인은 초기화한다. Tier 배정과 난이도 정책은 유지한다.

후보 조회는 키나 Provider API를 읽지 않으므로 마지막 확인 상태를 표시한다. 실제 키가 변경되었으면
전송 직전 검사에서 차단된다. 실제 계정 자체의 조건 변경은 같은 API 키를 유지할 수 있으므로 식별값만으로
탐지할 수 없으며, 이 때문에 비용 상한을 낮추지 않는다.

## Fallback과 조회 한계

승인된 현재 모델이 Rate Limit에 걸리면 기존 모델 cooldown과 사용자 Tier 순서대로 다른 승인 후보를
탐색한다. 미승인 유료 후보는 전체 유료 허용이 꺼진 상태에서 실행하지 않는다. unavailable로 기록한
모델은 모델별 승인 경로에서 제외한다. 타임아웃·네트워크 오류는 재시도하지 않고 미확인 비용 예약을 유지한다.
일반 429는 분당 제한·출력 토큰 제한·유료 사용 제한 등도 나타낼 수 있어 무료 잔량 소진으로 자동 기록하지 않는다.

이번에 확인한 공식 자료:

- [Gemini Billing](https://ai.google.dev/gemini-api/docs/billing): Free/Paid 계정 조건과 결제 연결 안내.
- [Gemini Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits): 프로젝트별 제한, AI Studio의 현재 한도 확인, 여러 429 원인.
- [Gemini Pricing](https://ai.google.dev/gemini-api/docs/pricing): 모델별 무료/유료 티어 조건.

현재 레지스트리에서 무료 티어가 명시된 모델은 Gemini 2개다. 일반 추론 API 키로 현재 무료 잔량을
확인하는 공식 API는 위 문서에서 확인하지 못해 자동 동기화 기능을 추가하지 않았다. 관리용 Cloud 권한을
추론 키로 대신하지 않으며 기존 계정 사용량 집계를 무료 잔량으로 변환하지 않는다.

## Routing Policy 드래그 앤 드롭

현재 난이도 안에서 Tier 행을 다른 Tier 행으로 드래그해 순서를 바꾼다. 위로·아래로 버튼도 유지한다.
다른 난이도, 미포함 Tier, 외부 텍스트, 여러 항목 드롭은 거부한다. 같은 Tier에 드롭하면 저장하지 않는다.
변경은 기존 `routing-policy-set` 경로로 저장하며 실패 시 이전 서버 설정과 오류를 표시한다.
